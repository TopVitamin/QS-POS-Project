# POS前端原型走查报告

> 日期：2026-10-16。对照[前端设计说明](前端设计说明.md)、[待改项](待改项.md)和`01-全局背景信息`第1至12篇。只记录现状，本轮不改业务代码。
>
> 核对方式：通读三端路由与全部 `*Page.vue`、`src/shared/api`、`mock/hub.ts`、权限矩阵和种子测试；抽查设计说明 §3–§6 与全局规则 §二/§四/§六、模式说明 §2.1–2.3、角色权限原则。未再跑浏览器点选；页面外观以既有截图脚本结果为辅。构建通过、种子测试通过不能代替交互走查。

## 一、结论

设计说明 §3 的三端页面和路由一一对应，没有空壳菜单。直营/加盟代销三条已确认口径（货权在强盛、应缴不含线上核销、POS不扣分成）在日结、应缴和结算单上是守住的。自提核验顺序、代发扣被路由店库存、停接后中枢拒派，与背景一致。三端业务库共用 `qs-pos-demo`，列表页普遍按授权店过滤。

主要缺口不在缺页，而在：**核销演示捷径把完整待核销提货码（含他店）铺在工作屏上**；**结算只校验不锁库，收齐款后中枢仍可能拒绝**；封账当天无法再开班退货；收货/盘点能把库存不变量打穿。权限在按钮层大体正确，读接口多数不绑会话，按单号可看到授权范围外的单据。

下面每条都给出位置、现象、严重程度和建议。已在[待改项](待改项.md)登记且实现与登记一致的，不重复列为新缺陷，见第五节。

## 二、问题清单

### 高

#### H1 核销工作屏展示他店完整待核销提货码

- **位置**：`src/apps/cashier/pages/PickupPage.vue`（`pickups()` 未传 `storeIds`，`demoCodes` 把 `storeId !== 本店` 的 pending 单完整码画在按钮上）；`src/apps/mobile/pages/PickupPage.vue` 同样逻辑。
- **现象**：万象天地店收银/移动「演示用提货码」除本店码外，会露出科技园店、加盟店的 6 位待核销码。点下去会被中枢以门店不一致拒绝，但码本身已经可见。履约列表、日志、追溯对 pending 用的是 `maskCode`（只露前 3 位）。
- **对照**：设计说明 §5.1「待核销的码在履约列表、操作日志、追溯链和库存详情的锁定明细里只露前3位，完整的码只在顾客手机上」。角色权限原则 §二同一口径。演示入口 `portal/App.vue` 有说明「正式系统里提货码只在顾客手机上」，核销页把同一套码直接铺在操作面上。
- **建议**：核销页 `pickups({ storeIds: [本店] })`；演示捷径对本店 pending 也用 `maskCode`，或只提供「可核销 / 门店不一致 / 已过期」三类占位，完整码留在演示入口并标明非正式。他店码改为手输或固定假码 `000000` 一类，不要用真实 pending。

#### H2 结算不锁库，收齐款后中枢仍可拒绝可用量

- **位置**：`src/shared/api/sales.ts` `startCheckout`（只 `checkAvailability`，不锁定）；`completeCheckout` → `hub.postSale` 再次校验，失败抛 `HubRejection`，本笔 `command` 回滚故不生成销售单，但此前 `pay()` 已提交成功的支付流水。`PayPage.vue` 会提示「没有生成销售单」并引导撤销。
- **现象**：万象天地店有 01、02 两台收银。A 台点结算通过后去收款期间，B 台或自提锁定、门店代发可以把同一 SKU 卖光/锁光。A 台收齐款后 `postSale` 拒绝：钱已收、没有销售单、库存未扣。关掉页面前若不点「撤销收款」，该台会留下「还有一笔没收完的结算」，下一笔开不了单。
- **对照**：全局规则 §二「开单保存时，本次数量不得大于该店当前可用。中枢拒绝后，不能改成本地已售」。后半句做到了（没有本地已售）；前半句只在进支付前闪验一次，中间没有配额。背景「超卖容差、负库存销售……不设允许卖超几件」。
- **建议**：`startCheckout` 向中枢申请短时预占（或复用自提锁库语义的演示锁），`completeCheckout` 转正式扣减、撤销/超时释放。至少在 `completeCheckout` 失败时自动走已有的 `cancelCheckout` 原路退，不要只靠店员点按钮。种子测试补「两台收银抢同一件」。

### 中

#### M1 当日日结封账后无法再开班，也就无法退货

- **位置**：`src/shared/api/shift.ts` `open`：已有当日 `dailyCloses` 则「今天已经日结封账，不能再开班」。`sales.createReturn` 依赖当前开班班次。
- **现象**：店长封账后，本营业日不能再开班。顾客当天再来退货会被挡在登录/开班。次日开新班可以退昨日的单（`checkReturnable` 只拦跨店和已退完），退货记在次日 `bizDate`，进入次日日结/应缴，不改已封账原单。
- **对照**：设计说明 §4.2 / 全局规则 §六「日结封账后的更正走退货，不改已封账的原单」。待改项「重开已封账日结」是另一件事。缺口是：**封账之后到切日之前没有退货通道**。
- **建议**：允许在已封账日用「仅退货班次」或无班次退货（仍回传中枢、记次日或记调整单，由后续设计定单据类型）。页面写清「封账后请次日开班再退」若短期不改。不要用重开日结来凑这条。

#### M2 实收数量没有上限，可把账面抬到远高于出库

- **位置**：`src/apps/mobile/pages/ReceiveDetailPage.vue` 实收输入只滤非数字、最长 4 位；`hub.postReceipt` 对 `receivedQty` 只 `Math.max(0, floor)`，按实收 `move` 增加 `onHand`，多收只生成差异单。
- **现象**：出库 2 件可录实收 9999，本店账面立即增加 9999。差异单 `status` 一直是 `submitted`，中枢模拟器没有后续判责/冲回。
- **对照**：全局规则 §四「数量不一致时另记差异，不把实收改成与出库相同来做平」——允许多收/少收，但没有「可任意抬账面」。待确认-22 说在途短少不判责，不是允许无上限溢收。
- **建议**：录入与过账增加警告阈值（例如超过出库须二次确认）；差异单在模拟器里至少能「承认实收」或「按出库冲回溢收」。POS 仍不要替中枢判责。

#### M3 盘点过账不核对自提锁定，可打破「锁定 ≤ 账面」

- **位置**：`hub.postStocktake` 按实盘与账面差直接 `move` 调整 `onHand`，不看 `locked`，也不拒绝 `onHand - adjustment < locked`。`verifyPickup` 核销时 `onHand += -qty`，不检查 `onHand >= qty`。
- **现象**：某 SKU 账面 5、锁定 4。盘点实盘 2 并过账后账面 2、锁定仍 4，可用被 `availableOf` 收成 0，但锁定仍在。再核销会把账面打成负数。种子测试断言 `locked <= onHand`，只保证种子生成时成立。
- **对照**：全局规则 §二「现货和自提同一本账……不能卖出已被自提锁定的件数」；盘点「授权之后由中枢调整」。中枢调整不应留下锁定大于账面。
- **建议**：过账时若调整后 `onHand < locked`，拒绝过账或先要求处理对应自提单（释放/优先核销）。核销扣减前校验 `onHand >= qty`。补测试覆盖「盘后锁定仍在」。

#### M4 要货发运、退仓固定「深圳主仓」，未标明不是当前仓网

- **位置**：`hub.reviewReplenishment` / `approveRtw` 写死 `sourceNodeName` / `targetNodeName = '深圳主仓'`。管理端要货/退仓列表、移动端要货详情、中枢模拟器要货/退仓区展示该名称。代客路由卡片有 `AssumptionTag k="regionalNodes"`，要货/退仓链没有。
- **现象**：演示员会把「调出仓 / 退往 = 深圳主仓」读成已定仓网。待对齐事项 A02：五个区域仓取自阶段 5 叙事，不代表当前仓网。
- **对照**：`assumptions.regionalNodes`、设计说明 §6。POS 不选仓是对的；错在展示未挂演示假设。
- **建议**：要货、退仓、收货来源、Hub 退仓卡片统一挂 `regionalNodes`；toast 写成「演示默认仓：深圳主仓」。

#### M5 重置演示库不清收银购物车和挂单

- **位置**：业务库 `localStorage['qs-pos-demo']`，`resetDb()` 只重建这一份。收银购物车/挂单/进行中结算 id 在 `qs-pos-cashier-cart`，会话在 `qs-pos-cashier-session`。`MePage` / `HubPage` / `AdminLayout` / 演示入口的重置都不清后两个键。
- **现象**：重置后管理端、移动端看到新种子，收银端仍可能挂着旧购物车，或 `checkoutId` 指向已不存在的结算。三端「同一份演示数据」在重置这一刻不一致。
- **对照**：设计说明 §8.3、`mock/db.ts` 注释「三个端共用」。
- **建议**：`resetDb` 同时删除 `qs-pos-cashier-cart`（以及过期 `checkoutId`）。会话键可保留身份，但 `shiftNo` 若已不在新种子里应清空。重置文案写上「挂单也会清掉」。

#### M6 店间调拨按演示假设可选任意店，因而能看他店可用量

- **位置**：`storeops.createTransfer` 只 `requirePerm(..., 'storeops.manage', toStoreId)`，不校验 `fromStoreId` 是否在操作者范围。`TransfersPage.vue` / `TransferPage.vue` 的调出店来自 `api.master.stores()` 全量，并用 `api.stock.list([fromStoreId])` 显示「调出店可用」。
- **现象**：松山湖店店长可把万象天地店、千灯湖店列为调出店，并看到对方可用件数。单据提交后由中枢审核发运。
- **对照**：设计说明 §6 `storeTransfer`、待确认-26「演示允许任意两家演示门店走单据」——跨店调拨是故意的。角色权限原则 §二「员工只看授权范围内的店」——看他店库存不是故意的副产品。两条口径目前并立。
- **建议**：继续允许跨店申请的话，调出店可用改为「发运时由中枢校验，申请页不展示他店数字」；或调出店选项仍全量，库存只显示「有/无」。若以后收窄到同模式/同加盟商，把假设和 UI 一起改，不要只改一处。

#### M7 按单号读取的详情接口不校验门店范围

- **位置**：`sales.get` / `sales.getReturn`、`storeops.shipment` / `stocktake`、`shift.get` / `shift.report`、`franchise.settlement` 均按单号取全文。收银 `DonePage` `/done/:no`、移动收货/盘点详情路由直接吃 URL。列表接口在页面传入 `storeIds` 时是过滤的。`audit.trace` 有范围校验，与上述不一致。
- **现象**：原型 API 跑在浏览器里、不绑会话。知道或猜到他店单号（演示前缀加日期序号），即可在本机读到行明细、支付、会员手机号、出库件数。加盟商财务改 URL 看另一加盟商结算单同样成立。
- **对照**：角色权限原则 §二授权到店。这是 mock 架构问题，不是菜单漏藏。接真实后端时若仍只信前端传的 `storeIds`，会变成真实越权。
- **建议**：所有 get-by-id 与 `requirePerm` 同一套：单据 `storeId`（或加盟商 id）必须落在操作者 `scopeStoreIds` / `scopeFranchiseeIds`。`permissions.test.ts` 目前只测矩阵，不测这一层。

#### M8 班次跨北京时间零点时，销售营业日和班次营业日会错开

- **位置**：`shift.open` 把 `bizDate` 写成开班当日；`completeCheckout` 把销售 `bizDate` 写成成交当时的北京日期。日结按「店 + 营业日」分别汇总班次和销售。
- **现象**：若班次跨过零点（演示店营业时间写 10:00–22:00，系统不强制交班），零点后成交记入次日日结，班次仍挂在昨日。昨日日结含这个未交班班次会封不成；次日日结有销售却可能没有对应班次。加盟应缴跟着销售营业日走，现金却还在未交的班里。
- **对照**：`assumptions.bizDay`「按自然日切日」、待确认-10。没有「跨日必须先交班」的硬校验。
- **建议**：成交时若 `todayBizDate() !== shift.bizDate`，拒绝收款并要求交班重开；或开班后跨日自动提示。与切日规则一起改，不要只改汇总。

### 低

#### L1 工作台「门店排行」「客单价」未标明演示口径

- **位置**：`DashboardPage.vue` 门店排行用授权范围内全部演示店；客单价 = 当日收款合计 / 成交笔数。`HomePage.vue` 同样有客单价。门店名册页已挂 `storeRoster` 和待确认-42/50，工作台没有。
- **现象**：四家演示店排行、客单价数字容易被读成公司 KPI 或开业名册。待确认-43 明确没有门店客单价名册级事实。
- **建议**：排行旁挂 `storeRoster`；客单价旁注明「本店/授权店当日演示汇总」或待确认-43。

#### L2 开班备用金快捷金额未挂待确认-10

- **位置**：`LoginPage.vue` 快捷 ¥200 / ¥500 / ¥1000；种子默认备用金 500 元。
- **现象**：像制度标准。交班差异阈值、备用金政策在待确认-10，页面只在交班差异处挂了假设。
- **建议**：开班区加「演示常用金额，非备用金制度」。

#### L3 非法路由静默回到首页

- **位置**：三端 `router.ts` 的 `/:rest(.*)*` 分别 redirect 到 dashboard / sale / home。
- **现象**：输错 hash 没有任何「没有这个页面」的提示，评审会以为功能被吃掉。
- **建议**：一页简单的「没有这个页面，回工作台」。

#### L4 移动端代客下单可在未填顾客时点提交

- **位置**：`AgentNewPage.vue` 提交按钮主要看是否已选商品；`fulfil.createAgentOrder` 才校验导购、姓名、11 位手机、地址长度。
- **现象**：先点提交再弹 API 错误。收银端代客页表单更完整。
- **建议**：按钮 disabled 与 API 规则对齐，或 `van-field` rules。

#### L5 权限矩阵里「授」和「看」一样直接给权限

- **位置**：`permissions.ts` `permsOfDuty`：`level !== 'none'` 就把 `row.perms` 全加上，只有 `do` 才读 `DO_EXTRA`。财务「查看全部加盟商结算」是授，实际直接拥有 `settlement.viewAll`。QS9002 种子已写入甲、乙，页面没有第二人确认。
- **对照**：设计说明 §5.2「授是可以发起，但要授权人确认后才能完成」。盘点过账走了 `AuthorizeModal`，结算「授」没有对应交互。
- **建议**：授类权限要么做成授权弹层，要么改表改成「看」并在账号上写死 `settlementFranchiseeIds`。不要一种级别两种行为。

#### L6 设计写「店长不登录收银」，演示账号店长都兼收银

- **位置**：设计说明 §5.1「店长……在收银端只当授权人……不登录收银」。种子 QS1001 / QS2001 / JMA101 / JMB101 都带 `cashier`，可以开班收款。实现按兼岗组合职责，与 §5.3 账号表一致。
- **现象**：只读 §5.1 会以为店长进不了收银端。不是逻辑错误，是两节口径叠在一起。
- **建议**：§5.1 加一句「演示账号店长兼收银，因此能登录；纯店长职责不能进收银端」。

#### L7 大量状态底色未走 tokens

- **位置**：管理端 `Hint.vue`、日结/收银核销成功条、移动端 Home 等使用 `#FDF3E3`、`#166534`、`#E8F7EE` 等。`AGENTS.md` 要求颜色从 `tokens.ts` 取。
- **现象**：预警/成功态和标签组件不完全同源，后续改主题会漏。
- **建议**：收敛到 `semantic.*Soft` 或 Uno 语义类。不挡演示。

## 三、已核对、与设计/背景一致的部分

| 主题 | 结论 |
| --- | --- |
| 页面清单 | 收银 9、移动 §3.2、管理 §3.3 均有路由和页面；销售详情是列表子页，不是漏菜单 |
| 直营 vs 加盟 | 加盟改价关闭；日结仅加盟生成应缴；直营日结无 `franchiseDueNo`；应缴按支付方式净额，不含自提 `paidAmount`、代客 `referenceAmount`；结算分成/佣金/赔偿 `amount: null` |
| 自提 | `judgePickup` 顺序：不存在 → 门店不一致 → 已核销 → 过期 → 锁定无效；成功才扣账面并释放锁定；核销不加成交净额；停接后门枢 `createPickupOrder` 拒绝 |
| 代发 | 区域仓发货不扣发起店；门店代发扣 `nodeStoreId`；拒单回 `submitted` 并清节点；POS 不选仓、不选承运商（承运商在 hub 发货时写入演示用顺丰） |
| 调拨 | 申请不改可用；发运扣调出店、调入店记在途；收货走既有出库单 |
| 权限按钮 | 总部运营店务为看；`storeops.manage` 仅店长类职责；加盟商财务 `scopeStoreIds` 只有本加盟商门店；系统管理无交易/店务/应缴菜单；交班校验本人班次 |
| 顾客字段 | 履约列表加盟店不展示顾客；抽屉里姓名/手机/地址走脱敏。核销通过后展示脱敏提货信息，加盟带待确认-52 |
| 三端数据 | 业务读写都经 `shared/api` → 同一 `qs-pos-demo`；`useRequest` 默认监听 `onDbChange`（含 `storage` 跨页）。例外见 M5 |
| 主数据 | 不回写；不展示成本/供应商价 |
| 编造数据的标注 | 门店名册、SKU/条码、演示前缀、PIN、促销规则、结算周期，在种子头或页面上多数已标演示/待确认。未标的见 M4、L1、L2 |
| 待改项「已演示」 | 店间调拨、门店代发、停接可走通，闭环依赖中枢模拟器，与设计 §8.3 一致 |
