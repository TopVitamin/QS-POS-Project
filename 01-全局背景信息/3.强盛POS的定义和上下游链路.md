## 一、门店触点指什么

POS是强盛自研的门店侧系统。它不拥有可售库存、订单路由和会计凭证，只承接店里的人能完成、能留下证据的那一层。

| 职责 | 说明 |
| --- | --- |
| 进店交易 | 开单、收款、退换、打印小票，记下导购归属 |
| 到店履约 | 核销中枢已经锁定并下发的自提单；现场无货时发起代客下单 |
| 店务 | 要货、收货、盘点、报损、交接班和日结 |
| 结果回传 | 把成交、核销、收货和盘点差异交给中枢。中枢记账 |
| 隔离与留痕 | 员工看授权范围内的店。加盟商只看本加盟商。改价、反结账、离线补传要有操作者和时间 |

**不由POS承担的工作：**

- 全渠道可售数量的计算，活动锁库的裁决，订单派到哪一个仓或哪一家店。
- 区域仓的上架、拣货、打包和干线调度。
- 应收应付、收款入账、核销、凭证、总账、存货成本。
- SKU、价格、门店、组织主档的创建和修改。
- 采购订单、供应商交期和工厂外箱码。
- 小程序上的浏览、下单和提货码展示。
- 含装修折旧的门店利润。

## 二、各系统分工

```plain
顾客在小程序下单，或在店里由导购开单
        │
        ▼
中央 OMS / 逻辑库存 ──锁库、路由、履约状态──► POS 只核销和回传
        │
        ├── 区域仓履约指令 ──► WMS 拣发
        │
        ├── 已审核销售、退货、盘点差异 ──► 业财编排 ──► 金蝶云·星空
        │
主数据平台（阶段5目标）──SKU、价格、门店、组织、导购──► POS 只读

支付通道 ◄── POS 调起收款，支付流水号回到交易
领星、聚水潭不连接 POS
SRM 不连接 POS
```

| 系统 | 承担的工作 | 和POS的交界 |
| --- | --- | --- |
| 中央OMS | 全渠道订单清洗、防重、四维路由、自提和代发的履约状态 | 下发本店待核销的履约单和提货码；接收核销结果；接收代客单并决定由哪个节点发货 |
| 逻辑库存 | 渠道配额、门店微仓和代销仓的可用、锁定、扣减 | POS申请锁定或提交执行结果。可售数量以中枢为准 |
| 自研ERP | 阶段4起的业务中枢：采购、批发、逻辑库存、单据编排 | 门店结果最终要能落成ERP已有或将来扩展的结果单，再进业财。ERP一期没有POS模块，见[待对齐事项A03](12.待对齐事项.md) |
| 业财编排 | 把业务结果整理成可以进财务的单据，并带上原始单号 | POS不直接生成凭证。推送金蝶的对象见[待对齐事项A07](12.待对齐事项.md) |
| 自研WMS | 仓内收货、上架、拣货、盘点 | 代发在区域仓执行。与POS不直接对账。WMS仓库一期是四个海外仓，见[待对齐事项A02](12.待对齐事项.md) |
| 微信小程序 | 顾客浏览、下单、选自提门店、出示提货码 | 订单进OMS。到店核销在POS。小程序是否本仓库范围，见【待确认-45】 |
| 主数据平台 | 阶段5叙事里SKU、客户、组织的唯一源头，并分发到POS | POS只接收。门店档案、导购工号、价格的维护不在POS。时点差异见[待对齐事项A09](12.待对齐事项.md) |
| 金蝶云·星空 | 存货核算、应收应付、总账、审计底座 | 不做门店开单入口。不与POS直连 |
| 支付通道 | 微信、支付宝、银联等收单和对账文件 | POS调起支付，保存通道流水号。直连还是聚合服务商，见【待确认-40】。加盟店用谁的商户号，见【待确认-16】 |
| 领星 / 聚水潭 | 跨境和国内电商的运营、履约 | 不对接POS。它们的订单若路由到门店，先变成OMS的履约单 |
| 指标平台 / 观远BI | 统一指标，叙事里含门店装修折旧 | 抽取中枢和金蝶。不在POS内再定义一套净利 |
| SRM | 供应商确认交期、箱码和预约 | 不对接POS。采购订单在SRM创建，推给ERP，再推给仓库 |

阶段5背景把深圳、嘉兴、天津、成都、武汉写成自研WMS，并把门店微仓画进履约网络。ERP立项时点写的是深圳主仓当时没有专业WMS。这些是不同时点的口径。POS店务对接的是中枢里的门店库存，不是去指挥WMS的库位，见[待对齐事项A02](12.待对齐事项.md)。

## 三、业务链路

### 3.1 进店现货

```plain
导购或收银登录
    → 扫描条码或序列号，读取已经下发的价格
    → 向逻辑库存确认本店微仓或代销仓仍有可用量
    → 调起支付
    → 支付成功后回传成交
    → 中枢扣减并形成可以进业财的结果
```

POS上看到的可用量是中枢的投影。本地又记一本「卖完才减」的可售账，会把自提锁库再次打穿。见[待对齐事项A05](12.待对齐事项.md)。

断网时，允许范围内的现金和已经得到通道结果的支付可以先写入本地账本。联网后回传，中枢按来源单号去重。自提核销不在这一条里，见3.2。限额见【待确认-09】。

### 3.2 小程序自提

锁库和提货码在中枢完成。POS不生成提货码。

```plain
顾客在小程序选自提门店
    → 中央库存锁定该店配额
    → 锁定成功才出现动态提货码
    → 到店后 POS 扫码，核验门店、有效期和是否已经核销
    → 核销结果回传，中枢扣减
```

锁定失败、提货码过期、门店不一致或已经核销，POS拒绝完成出库，并给出代客下单入口。完全离线时不能把核销做成出库。可以登记一条待处理，但那不是核销完成。截止时长、部分提货、取消后额度如何释放，见【待确认-04】。无码核销见【待确认-05】。

核销在POS是只留下交付记录，还是同时产生一张金额为零的销售单，要和营收确认一起定，见【待确认-14】。在此之前，设计不能把核销金额再加进门店营业额。

### 3.3 缺货代发

```plain
导购在 POS 发起代客下单（顾客、商品、门店、导购工号）
    → 中央 OMS 按路由选择履约节点
    → 区域仓由 WMS 拣发
    → 履约状态回到 POS，供门店查看
    → 业绩记在发起的门店和导购工号上
```

POS不选择承运商，也不承诺时效。叙事里的承运是顺丰，是不是唯一承运商见【待确认-47】。先占库还是先收款、顾客改为线上支付的情况，见【待确认-06】。

加盟店被选为发货店时，线上订单的钱不经过门店，只记履约佣金。佣金规则见【待确认-20】。

### 3.4 要货、收货和盘点

```plain
店里提交要货
    → 中枢审核
    → 审核通过后形成区域仓到门店的调拨指令
    → 门店按出库单收货，差异单独成单
    → 盘点差异经授权后，由中枢调整库存
```

要货单是申请，不是仓库的出库指令，也不是已经增加的库存。ERP已有分步式调拨单、调出通知单、调入通知单和直接调拨单。门店这条链落成哪几张、前缀是否复用，见【待确认-01】【待确认-41】。未确认前，POS不另下一张让WMS直接执行的出库单。

收货之前，货还在途。在途短少和破损由谁承担，见【待确认-22】。盘点期间卖不卖、抽盘差多少算通过，见【待确认-15】。

加盟店要货走同一条调拨，不产生货款，不做订货资金校验。见[模式说明](7.直营与加盟代销模式说明.md)。

### 3.5 退换货

本店售出、本店退回：POS验货，按原支付路径退款，库存回到本店微仓或代销仓。换货用一张退货加上一张新的销售来表达，不另造一种库存对象。

原单在线上、人到店里退：门店验货收货，退款由中枢按原渠道退。直营和加盟之间能不能互退，见【待确认-27】。组合支付先退哪一种，见【待确认-08】。

### 3.6 日结、营业款和金蝶

直营店的日结核对班次里的支付方式和现金。钱进强盛的收款主体。

加盟店的日结封账之后，由中枢按营业日生成应缴营业款。分成、履约佣金、退货冲回和盘亏赔偿进结算单。结算单放在中枢还是金蝶，见【待确认-38】。POS可以查看，不能在店里改应缴金额。

```plain
POS 成交、退货、盘点差异（带原始单号）
    → 中枢形成已审核结果
    → 业财编排
    → 金蝶云·星空
```

阶段5叙事写业财编排自动生成凭证，并且每张凭证带原始业务单据号。ERP定稿是ERP不建凭证。两条同时存在时，POS只保证原始单号可以被引用，不实现生成凭证，见[待对齐事项A07](12.待对齐事项.md)。

### 3.7 主数据

```plain
SKU、条码、价格、门店、组织、导购工号
    → 单向进入 POS
    → 成交时保存价格和规则的快照
    → POS 不回写主档
```

门店需要改零售价时，走授权，并留下前后值。授权通过之后，仍然不把POS变成价格的源头。加盟商能否在价格带内调价，见【待确认-34】。促销规则从哪个系统下发，见【待确认-46】。

## 四、数据往哪边流

| 方向 | 传什么 | 说明 |
| --- | --- | --- |
| 主数据 → POS | SKU、条码、价格、门店、组织、导购 | POS不回写。快照只留在成交上 |
| POS → 逻辑库存 | 锁库申请、成交、核销、收货、盘点差异 | 申请可以被拒绝。拒绝后店里不能先卖出 |
| 中央OMS → POS | 本店待核销履约单、提货码、代发状态 | 履约单的源头不在POS |
| POS → 中央OMS | 核销结果、代客单 | 代客单不包含POS自己选好的仓库 |
| OMS → WMS | 区域仓的发货指令 | POS不发这张指令 |
| POS → 支付通道 | 收款和退款请求 | 以通道返回的流水号为准。不明结果要查单，不能在POS里标成成功 |
| 支付通道 → POS | 支付结果、对账文件所需的流水号 | 对账文件本身不是门店日报 |
| 中枢 → 金蝶 | 已审核结果 | 订单、核销过程、班次、对账草稿不代替结果单 |
| POS → 商场 | 租约要求时的销售数据 | 上传失败不取消POS已经成交的交易。范围见【待确认-02】 |
| SRM、领星、聚水潭 ↔ POS | 不直接传递 | 库存和订单都先经过中枢 |

推送失败时，不在POS里另建一张业务单去「把库存补上」。已经在中枢生效的扣减，不以POS本地删除为回滚。

## 五、三条必须先记住的边界

1. **核销不是锁库。** 提货码能核销，是因为中枢已经锁住了这家店的配额。POS不能在锁库失败时仍完成自提。
2. **代客单不是发货指令。** 仓库只执行中枢给出的履约。POS不指定库位，也不指挥WMS。
3. **日结不是凭证。** 营业款、分成和总账在中枢与金蝶。POS提供的是班次、支付流水和原始交易号。

字段、状态机、页面和接口放在后续的需求与产品设计里。本文的链路表示目标边界，不表示接口已经联调。标了【待确认】的，不能当成验收条件。
