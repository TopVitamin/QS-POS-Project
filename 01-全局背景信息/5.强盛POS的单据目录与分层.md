# 强盛POS的单据目录与分层

> 更新日期：2026-10-15。
>
> 本文只回答两件事：门店侧有哪些业务对象，它们相对ERP三层和中枢各落在哪。状态有哪些取值、谁可以点哪个按钮、字段如何校验，都放在后续的产品设计里。本文不设状态机，也不列字段。
>
> ERP三层的权威说明是[《5.强盛ERP的单据分层设计》](https://github.com/TopVitamin/QS-ERP-Project/blob/main/01-全局背景信息/5.强盛ERP的单据分层设计.md)。POS不另创一层库存结果。

---

## 一、为什么要挂到已有的分层上

ERP已经把一笔业务拆成三件不同的事：

| ERP层级 | 回答什么 | 和门店可能相关的单据 |
| --- | --- | --- |
| 业务安排 | 一共约定做什么 | 销售订单、销售退货单、分步式调拨单 |
| 执行指令 | 这一批交给谁执行 | 销售发货通知单、调出通知单、调入通知单 |
| 实际结果 | 实际收进或退出多少 | 销售出库单、销退入库单、直接调拨单、其他出入库 |

门店如果再做一本「可售库存」，或者再下一张让区域仓直接拣货的指令，同一件货就会有两套账。所以POS的对象只允许三类：

1. **门店执行记录。** 店里真实发生的成交、收款、核销、收货、盘点和交班。它们是事实的原始记录，库存是否变化看中枢有没有接受。
2. **向中枢发起的申请。** 锁库申请、代客单、要货、调拨申请。同意与否、派到哪里，由中枢决定。
3. **中枢单据的投影。** 自提履约单、主数据、代销仓库存、应缴营业款和结算单。POS只读或只回写执行结果，不成为这些单据的源头。

进店成交通常没有事先在ERP里做一张B2B那种销售订单。因此POS销售单首先是门店执行记录，不是ERP第一层的另一张销售订单。它要进入财务时，由中枢形成实际结果。结果单用不用现有的销售出库单前缀，见【待确认-01】【待确认-14】。

## 二、对象目录

「段」沿用[项目背景](2.强盛科技POS项目的背景信息.md)：第一段是直营交易和店务，第二段是加盟、商场报送和审计抽样。标了待确认的，目录里先留名字，不表示已经纳入本期。

| 对象 | 段 | 相对中枢的位置 | 谁产生 | 结果落在哪 |
| --- | --- | --- | --- | --- |
| 门店、收银台 | 第一段 | 主数据投影。收银台是否由主数据编号见【待确认-01】 | 上游下发门店；收银台在店里启用 | POS不改门店档案 |
| 班次、钱箱事件 | 第一段 | 不进入ERP单据层 | POS | 只说明这一班的现金和备用金。不产生库存 |
| 日结单 | 第一段 | 门店营业日的封账记录 | POS封账，中枢读取 | 直营店到此为止。加盟店由此触发生效应缴，应缴单不在POS生成 |
| POS销售单 | 第一段 | 门店执行记录 | POS | 回传后由中枢扣减并形成业财结果。不平行记可售账 |
| 支付流水 | 第一段 | 附在销售或退货上 | POS按通道结果写入 | 不明结果保持未完成。不生成凭证 |
| 退货单 | 第一段 | 门店执行记录 | POS。跨店和无原单是否要中枢同意见【待确认-27】【待确认-51】 | 库存回到本店对应的微仓或代销仓。换货不单建对象，用退货单加新销售单表达 |
| 自提履约单 | 第一段 | OMS执行视图的投影 | OMS下发 | POS不改商品和数量 |
| 核销记录 | 第一段 | 附在履约单上 | POS | 成功之后中枢扣减。是否另生一张零金额销售单见【待确认-14】 |
| 代客单 | 第一段 | 申请，不是发货指令 | POS发起 | OMS生成履约。区域仓结果在WMS和中枢 |
| 锁库申请 | 第一段 | 申请的影子 | POS发起，中枢裁决 | POS只保留申请和结果。失败不等于可售 |
| 要货单 | 第一段 | 申请 | POS发起，中枢审核 | 审核通过后的调拨指令在中枢。单据类型见【待确认-01】 |
| 收货单、差异单 | 第一段 | 门店执行记录 | POS | 实收和差异回传。不把实收改成与出库一致 |
| 盘点单 | 第一段 | 门店执行记录 | POS | 差异授权后由中枢调账。冻结销售与否见【待确认-15】 |
| 退仓单 | 第一段 | 申请 | POS发起 | 门店退回区域仓。加盟店的残次、滞销、质量件也走退仓，不因此产生返款 |
| 店间调拨申请 | 第一段 | 申请 | POS发起 | 是否允许见【待确认-26】。未允许前不列入一期必做 |
| 门店库存流水 | 第一段 | 回传，不是可售真相 | POS按每次动货产生一条 | 与中枢流水对得上。对不上时以中枢已接受的结果为准 |
| 序列号事件 | 第一段 | 事件。主档位置见【待确认-11】 | POS在收货、销售、退货、盘点时采集 | 不在POS建成公司唯一的序列号库，除非【待确认-11】改口 |
| 业绩归属 | 第一段 | 附在销售、退货、代客上 | POS按工号写入 | 提成金额不在归属确认前由POS计算，见【待确认-13】 |
| 操作日志 | 第一段 | 不是业务单据 | 系统写入 | 不参与营业额 |
| 加盟商、加盟合同 | 第二段 | 主数据投影 | 上游维护 | POS只读。三条已确认口径是合同上的常量 |
| 代销仓 | 第二段 | 中枢逻辑库存 | 中枢建仓 | 一店一仓是建议，见【待确认-22】。POS只读数量 |
| 应缴营业款、缴款记录 | 第二段 | 不进入POS单据层 | 中枢按营业日生成应缴；缴款由加盟商登记、中枢核对 | POS只读应缴。不在店里改数 |
| 分成流水、履约佣金 | 第二段 | 由成交、核销、代发、退货派生 | 中枢 | 规则见【待确认-18】【待确认-20】。未定规则前不自动出金额 |
| 盘亏赔偿 | 第二段 | 由盘点差异派生 | 中枢判责 | 损耗率未定时不生成赔偿金额，见【待确认-23】 |
| 加盟结算单、往来、保证金 | 第二段 | 业财对象 | 中枢或金蝶，见【待确认-38】 | POS只读。不付款 |
| 商场报送记录 | 第二段 | 附在销售上的外部回执 | POS按租约上传 | 上传状态不影响成交。哪些店要传见【待确认-02】【待确认-03】 |

下面这些名字在调研里出现过，强盛自己的资料没有要求本期一定要有，不放进上表的建设范围：

| 名字 | 为什么先不列入 |
| --- | --- |
| 预付款、信用额度、买断订货 | 加盟已确认为代销。要货不付货款 |
| 商场统一收银、扣点、商场对账单 | 不做。直营店租约若要求统一收银，见【待确认-02】，本层仍不设计这套结算 |
| 企微SOP、CDP | 见【待确认-37】 |
| 国补订单 | 商品是否适用见【待确认-12】。未适用前不单列单据 |
| 业绩调整单 | 能否事后调整见【待确认-13】。允许之后也不得覆盖原归属 |
| 零金额交付销售单 | 见【待确认-14】。未确认前，核销记录本身就要能被审计抽到 |

## 三、和ERP单据怎么配对

配对在前缀确认之前，只表示「应该能沿着单号追上去」，不表示POS已经占用了ERP的号码段。

| 门店对象 | 中枢或ERP侧 | 配对规则 |
| --- | --- | --- |
| POS销售单 | 中枢形成的销售结果。候选包括销售出库单，前缀XSCK是否复用见【待确认-01】 | 一笔进店成交对应一次库存扣减。不把POS销售单编号直接当成ERP销售订单XSDD。XSDD在ERP里用于B2B和独立站 |
| 退货单 | 销退入库单，前缀XTRK；POS退货是否另起前缀见【待确认-01】 | 退货单号和原销售单号互相引用 |
| 自提履约单 | OMS订单和锁库记录 | 核销记录引用履约单。线上原单的收款不在POS重做 |
| 代客单 | OMS新的履约 | 代客单号不代替仓库出库单号 |
| 要货单 | 分步式调拨或中枢另行规定的调拨链。前缀FBDB、DCTZ、DRTZ、ZJDB是否复用见【待确认-01】 | 未复用前，要货单只作为申请号。收货引用中枢出库单号 |
| 盘点差异 | 中枢调账。ERP一期不建盘点单，盘盈盘亏走其他入库、其他出库 | POS盘点单不直接推送金蝶 |
| 应缴营业款、结算单 | 业财或金蝶，见【待确认-38】 | 通过原始销售单号向上能找到班次和支付流水 |
| 采购链 | 无 | POS对象不引用采购订单。采购方向见[待对齐事项A04](12.待对齐事项.md) |

ERP单据前缀以[ERP编码规则](https://github.com/TopVitamin/QS-ERP-Project/blob/main/01-全局背景信息/6.强盛ERP的编码规则和通用字段规则.md)为准。国内电商订单GNDS、跨境电商订单KJDS是ERP里的订单，不是门店销售单。

## 四、追溯链要能串起来

阶段5要求抽到一笔交易时，能看到库存扣减、发货、发票、银行流水和凭证。POS负责店里的那几环。目标链条是：

```plain
金蝶凭证（不在 POS 生成）
    → 中枢已审核结果
    → POS 销售单或核销记录或盘点单
    → 支付流水 / 提货码 / 收货来源单
    → 班次和日结
```

加盟再向后多接应缴营业款、缴款和结算单。结算单还没定放在哪一边时，链条上不画一个空节点假装已经付款。

银行流水和凭证在金蝶。装修折旧在指标平台。POS不复制这两份账。

## 五、本文故意不写的内容

- 每张单据的状态名称、允许的跳转和并发。
- 表头表体字段、必填和默认值。
- 接口字段名、重试次数和错误码。
- 页面上按钮的位置。
- 支付通道返回码的枚举。

后续目录如果给销售单或核销记录设计状态，必须同时满足本文的分层：任何状态都不能表示「POS已经独自完成库存记账」或「POS已经指定仓库发货」。库存是否扣减，只看中枢是否接受；货从哪个仓发出，只看OMS的路由结果。
