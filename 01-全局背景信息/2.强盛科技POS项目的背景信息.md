## 一、为什么做

### 1.1 触发点

阶段4把后台主干收进自研系统之后，线下体验店仍然是空白。阶段5要在核心商圈开直营和加盟店，小程序还要把「到店自提」当成一种履约。2024年万象天地那一单说明：店、小程序和中央库存如果各记各的，线上已经卖掉的货，到店可以没有。

公司需要的不是再买一套把订单、库存、会员、财务都包进来的新零售中台。中央订单、逻辑库存、门店配额、代发路由和业财单据链继续留在自研中枢。POS要做的是店里的人能收银、能核销、能代客下单、能把要货和盘点交上去，并且每一笔都能点回中枢。

ERP一期已经写明不做POS、不做中央OMS。所以门店触点是独立项目，不塞进ERP销售模块。见[待对齐事项A03](12.待对齐事项.md)。

### 1.2 要对齐的缺口

| 缺口 | 背景里的表现 | POS要对准什么 |
| --- | --- | --- |
| 没有统一的店内交易入口 | 档口关掉之后，体验店尚未有自己的收银 | 进店成交、退换货、交班日结走同一套门店端 |
| 自提不锁库 | 小程序下单未锁微仓，到店扑空 | 锁库在中枢。POS核销前提货码必须已经锁定成功；核销结果回传 |
| 缺货靠工作群 | 导购私下找仓，业绩归属不清 | 代客下单带上门店和导购工号，路由由中央OMS完成 |
| 直营和加盟两套账的风险 | 数十家店将同时存在两种经营方式 | 一套POS，用门店模式区分。加盟三条口径已确认，见[模式说明](7.直营与加盟代销模式说明.md) |
| 微仓账面不可信 | 要货、收货、盘点、调货若仍在微信和Excel | 店务单据回传中枢。未入系统的调货不能当作库存已经变动 |
| 上市要追到店里的原单 | 尽调要求订单追到库存扣减、出库、发票、流水和凭证 | POS留下可被引用的原始交易号。凭证在金蝶，不在POS生成 |
| 利润口径各说各话 | 新零售曾经不含装修折旧 | POS不计算含折旧的门店净利。指标在指标平台 |

### 1.3 为什么自研，而不是把店开在另一套中台上

| 方案 | 能对照的能力 | 本项目的取舍 |
| --- | --- | --- |
| 有赞零售、微盟智慧零售 | 小程序、到店核销、导购业绩、加盟结算 | 核销和导购可以借鉴。订单和库存若交给它们，会和已经自研的中枢抢真相 |
| 银豹、客如云、科脉、思迅 | 收银、序列号、要货、盘点、加盟店管控 | 适合店内进销存闭环。接不住「中枢锁库 + 四维路由 + 区域仓代发 + 金蝶穿透」 |
| 海鼎、昂捷、伯俊 | 连锁总部、直营加盟、一盘货和门店POS | 品牌连锁流程接近。整包会把控制点再次放到外部中台 |
| Shopify POS、Lightspeed、Square | 到店自提、离线、序列号、员工提成 | 只作架构对照。国内支付、微信小程序和代销结算不在它们的主场 |

因此：门店交易和店务在本系统，锁库和路由在中枢，区域仓作业在WMS，法定账在金蝶，支付走外部收单。

公开能力摘录和来源URL见调研素材。竞品页面上有、强盛背景里没有的比例、天数和限额，不写进规则。

## 二、这个项目是什么

| 项 | 说明 |
| --- | --- |
| 项目名称 | 强盛科技自研POS（门店交易与店务触点） |
| 建设方式 | 云端加门店端。门店端覆盖收银机、平板和手机。不替换中央OMS、ERP、WMS、金蝶 |
| 核心定位 | 线下交易和店务：收银、退换、自提核销、代客下单、导购归属、要货收货盘点、交接班日结，并把结果交给中枢 |
| 服务对象 | 直营体验店和加盟体验店的导购、收银、店长；总部新零售、财务结算；加盟商的管理人员和财务 |
| 不承担的职责 | 不算全渠道可售库存，不决定订单派到哪一个节点，不生成会计凭证，不维护SKU主档 |

```plain
主数据单向进入 POS
    → 进店成交：POS 收款并回传，中枢扣减门店微仓
    → 小程序自提：中枢锁库并生成提货码，POS 到店核销
    → 现场无货：POS 代客下单，中央 OMS 路由到区域仓，WMS 拣发
    → 店务：要货、收货、盘点差异回传，库存结果由中枢记账
    → 已审核的销售和退货结果经业财进入金蝶，POS 不做总账
```

小程序负责顾客浏览、下单、选自提门店和出示提货码。它不是POS的一个页面。两者是否同一期建设，见【待确认-45】。

## 三、建设范围

范围分成两段，对应「先把直营店的交易和自提走通」和「再把加盟代销、审计抽样接上」。两段都还不是已确认的项目排期。字段、状态枚举和接口报文不在本篇展开。

### 3.1 第一段：直营交易和店务

这一段是本仓库所说的一期。

| 模块 | 要做什么 | 不在这一段里做完的 |
| --- | --- | --- |
| 账号与主数据 | 接收门店、SKU、条码、价格、组织、导购工号。POS只读 | 主数据平台在ERP一期尚未作为已交付系统，见[待对齐事项A09](12.待对齐事项.md) |
| 进店收银 | 开单、促销快照、支付、小票、退换货 | 电子发票由哪套系统开，见【待确认-31】 |
| 离线 | 断网时把允许的交易写入本地账本，联网后回传并去重 | 限额和时长见【待确认-09】。自提核销不在离线时完成 |
| 自提核销 | 看待核销列表，扫动态提货码，把核销结果交回中枢 | 截止时长、部分提货、无码核销见【待确认-04】【待确认-05】 |
| 代客下单 | 带上顾客、商品、门店和导购工号，提交给中央OMS | 先收款还是先占库，见【待确认-06】。路由不在POS |
| 导购归属 | 成交和代发都能记到工号 | 提成怎么算、谁发放，见【待确认-13】 |
| 店务 | 要货、收货、盘点、报损留痕 | 直送、直通、配销价见【待确认-41】。店间调拨是否允许见【待确认-26】 |
| 日结 | 班次、支付方式核对、门店日报 | 现金差异阈值和切日时点见【待确认-10】 |
| 留痕 | 改价、反结账、离线补传、代客下单记下操作者和时间 | 授权层级见【待确认-51】 |
| SN | 按商品配置采集，销售和退货能记下序列号 | 哪些品类强制、主档放在哪，见【待确认-11】。全链路对齐不作为一期完成条件 |

### 3.2 第二段：加盟、商场报送和审计抽样

| 模块 | 要做什么 | 还没定的 |
| --- | --- | --- |
| 加盟店交易 | 同一套收银和店务，库存记在强盛的代销仓 | 经营权、价格带见【待确认-35】【待确认-34】 |
| 营业款 | 日结后由中枢生成应缴营业款，再按周期结算归集 | 商户号、上缴方式、分成见【待确认-16】至【待确认-19】 |
| 路由 | 加盟店的代销仓可以被OMS锁定，用于自提和代发 | 履约佣金见【待确认-20】。线上订单的营业款不进门店应缴 |
| 商场报送 | 直营店进驻商场且租约要求时，上传销售数据 | 哪些店、什么接口见【待确认-02】【待确认-03】。不做商场统一收银 |
| 审计 | 随机一笔门店交易能点到中枢结果，再由金蝶继续往下 | 凭证生成不在POS。路径见[待对齐事项A07](12.待对齐事项.md) |

寻源、车间、区域仓WMS、企微SOP和CDP不放进这两段。会员一期只做到店识别和基础券、积分核销，深度运营见【待确认-37】。

## 四、不做什么

| 类别 | 不做什么 | 依据 |
| --- | --- | --- |
| 中枢 | 不在POS重建中央OMS、全渠道可售库存、四维路由、业财编排 | 用户已确认：锁库、路由、业财、主数据都在中枢 |
| 财务 | 不做总账、存货成本、税务申报、含装修折旧的净利 | 财务底座是金蝶。指标算法在指标平台 |
| 仓储 | 不做区域仓的收货上架、拣货、月台和干线调度 | 在WMS。门店微仓的店务才在POS |
| 供应 | 不做采购订单、外箱码、对账和工厂进度 | 采购订单在SRM创建，推给ERP，再推给仓库。POS不参与 |
| 前台电商 | 不替换领星、聚水潭的抓单和打单 | 电商订单进中央OMS，不进POS开单 |
| 小程序商城 | 不做C端浏览、会员触达和提货码展示 | 小程序是并列触点。核销动作在POS |
| 商场 | 不做购物中心级多租户平台，不做商场统一收银和扣点对账 | 只在直营店租约要求时报送销售数据。商场券是否核销见【待确认-49】 |
| 境外 | 不做多币种跨境门店 | 阶段5的门店在国内核心商圈。海外履约是FBA和第三方仓 |
| 加盟买断 | 不做先款后货的订货、预付款和信用额度 | 加盟已确认为代销，要货不产生货款 |

销售给消费者的退款、如果原单在线上渠道，由中枢按原支付路径退。POS在店里验货和收货，不把自己做成第二个退款出纳，除非这笔钱本来就是这家店收的。跨店时能不能退，见【待确认-07】【待确认-27】。

## 五、建议的落地顺序

下面是阅读和设计时的先后，不是排期。调研报告里的试点周数和批量月份是教学示意，不能当成开工日期。

1. 门店、商品、价格、导购工号的只读同步，以及本店数据隔离。没有档案和权限，后面的单据不能给店里用。
2. 进店现货收银、支付流水、退货，以及断网回传。先保证店里卖出的一件货，中枢只扣一次。
3. 自提核销。先解决「到店说没有」。
4. 代客下单和导购工号。先保证缺货有单据，而不是工作群。
5. 要货、收货、盘点、交接班日结。微仓账面要能对上锁库。
6. 直营店铺开之后，再做加盟代销的营业款、结算，以及按租约的商场报送、审计抽样。

第3步依赖中枢已经能锁定指定门店的配额。接口未定时，不能把「POS本地扣减一下」写成替代方案。见[全局业务规则](4.强盛POS全局业务规则与约束.md)。

## 六、部门在本项目里要什么

| 部门 | 诉求 | 在POS里的动作 |
| --- | --- | --- |
| 经营管理层（林强） | 到店不扑空；店要进全渠道；上市能抽到原单 | 不直接操作系统。加盟分成和经营权仍待拍板 |
| 新零售 / 营销 | 开店、体验、导购愿意接线上的单 | 提成制度和作业要求。提成计算见【待确认-13】 |
| 供应链和仓储（阿盛） | 微仓水位可信，代发不靠群消息 | 审核要货、安排区域仓发运。审核人见【待确认-48】。拣货在WMS |
| 财务（阿兰） | 日结、加盟营业款、金蝶能点回店里的单 | 定上缴和开票。付款和凭证仍在金蝶 |
| 数字化中心 | 边界清楚 | 主数据和接口只走中枢、支付和金蝶，不再加一套库存表 |
| 店长、导购、收银 | 开单快，提成算得清，无货时有代发入口 | 收银、核销、盘点、交班 |
| 加盟商 | 只看自己的店和结算 | 查看应缴和结算结果。结算单不在POS里改数 |

人物只帮助理解参与方，不映射账号和审批流。
