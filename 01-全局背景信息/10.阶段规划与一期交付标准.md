# 阶段规划与一期交付标准

> 更新日期：2026-10-15。
>
> 本文用「能把哪件已经发生过的事在系统里走完」来判断一期，而不是用功能条数。月份不是排期。调研报告里的试点周数和M1至M4是教学示意，本文不沿用那些起止时间。
>
> 课程叙事把门店放在阶段5。那是背景，不是本仓库的交付证明。试点店名单和历史数据如何进入系统，见【待确认-50】。抽盘差多少算通过，见【待确认-15】。

---

## 一、两段范围

| 段 | 对应的业务时点 | 完成时店里能做什么 | 明确仍不做 |
| --- | --- | --- | --- |
| 一期，直营交易和店务 | 先接住进店成交和自提扑空 | 直营店按中枢价格收银；断网交易回传且不重复扣减；自提必须锁库成功才能核销；无货时代客下单并带上工号；要货、收货、盘点、日结有单 | 加盟结算、商场报送、含折旧净利、区域仓WMS、凭证 |
| 阶段5增强 | 加盟店进入同一套路由，审计要抽到店 | 在一期之上，加盟店按代销收银；应缴由中枢生成；自提和代发能锁代销仓；租约要求的店能留下报送回执 | 总账、税务申报、分成比例的自行发明 |

两段的模块边界以[项目背景](2.强盛科技POS项目的背景信息.md)为准。这里只加「怎样算走通」。

没有【待确认-50】，下面的场景只能用指定的新店演示，不能声称已经开业的全部店都已迁移。

## 二、一期走通的五个场景

场景来自阶段5的门店坑，以及「微仓账面必须可信」这条约束。除了背景已经写死的「先锁库、再提货码、到店核销」，其余天数和阈值见对应的【待确认】。

### 2.1 进店卖出一件现货，只扣一次

```plain
导购开单并完成支付
    → 成交回传到中枢
    → 本店微仓库存减少这一件
    → POS 里不存在另一本已经减少、但中枢尚未接受的可售账
```

同一笔因超时重试再次到达时，库存和营业额都不再增加或减少第二次。

### 2.2 小程序自提不会到店扑空

对应2024年万象天地：下单未锁库存，最后2件被进店顾客买走。

```plain
顾客选自提门店
    → 中枢锁定该店配额成功，才给出提货码
    → 锁定失败时，顾客看不到可提货
    → 到店扫码，POS 核验门店和是否已核销
    → 核销成功后中枢扣减
```

锁定失败或已经核销时，POS不能把这一单做成出库。进店销售不能卖出已经被这张自提单锁定的数量。

### 2.3 现场没有货，用单据代发，而不是工作群

```plain
核销或开单时本店无货
    → 导购提交代客单，单据上有门店和导购工号
    → 履约节点由中央 OMS 决定
    → POS 能看到履约状态
    → 业绩归属记在发起的门店和工号上
```

POS画面上如果出现「已指定某仓某库位」，这个场景不算通过。提成金额可以还没算出来，见【待确认-13】。归属必须已经在。

### 2.4 断网卖掉的，联网后不是第二笔

```plain
断网期间一笔允许的现金或已成功支付写入本地账本
    → 联网回传
    → 中枢只接受一次
    → 自提核销在断网期间不能变成出库完成
```

限额还没有数，见【待确认-09】。演示时要标明所用限额是假设值。假设值不能写回本节成为规则。

### 2.5 要货收货和盘点对得上锁库

```plain
门店提交要货，审核前本店可用量不变
    → 按来源出库单收货，短少单独记差异
    → 盘点差异在授权前不改变可售
    → 没有单据的调货，两边可用量都不变
```

区域仓有没有扫码拣货，不作为POS一期的完成条件。那一段在WMS。

## 三、阶段5再走通的三个场景

这三件不作为一期完成的条件。

### 3.1 加盟店卖出，货和款各自归位

```plain
加盟店按强盛零售价成交
    → 代销仓库存减少，货权仍在强盛
    → 日结封账后，中枢生成应缴营业款
    → 线上自提核销不进入这张应缴
    → POS 不能改应缴金额
```

分成比例未定时，这个场景只验证应缴和库存，不验证结算单上的分成金额。见【待确认-18】。

### 3.2 加盟店被选为自提点

```plain
OMS 锁定该加盟店代销仓
    → 到店核销，不在店里再收一次线上的钱
    → 履约记录能指回原订单和门店
```

佣金金额见【待确认-20】。金额未定，不挡住「锁的是这一家店」这件事。

### 3.3 抽一笔店内交易能往下看见原单

```plain
指定一笔已回传的 POS 销售或核销
    → 看到支付流水或提货码、班次、日结
    → 看到中枢已经接受的库存结果单号
    → 凭证和银行流水从金蝶继续往下，不在 POS 里做一张假凭证
```

直营店若有商场报送，还要能看到回执。没有租约的店，链条上不出现报送节点。

## 四、怎样还不叫完成

| 现象 | 为什么不算完成 |
| --- | --- |
| 小程序可以下自提，但锁定失败仍显示可提 | 一期要避免的就是到店扑空 |
| 核销成功只写在POS本地，中枢库存未减 | 锁库和记账不在POS |
| 代客单由店员选定仓库和承运商后直接发运 | 路由不在POS。见[待对齐事项A03](12.待对齐事项.md) |
| 断网交易回传了两次，库存少了两件 | 去重没有生效 |
| 微信里调货之后，自提锁库跟着变了 | 无单据的调货不能改可用量 |
| 加盟店日结时店员自行填了一个分成金额 | 分成不在POS里现算。口径见【待确认-18】 |
| 演示数据能走通，但支付或中枢没有联调记录 | 演示只证明流程表达，不证明通道和金蝶已经接通 |
| 用名创或小米的比例把结算单算平 | 那不是强盛的数 |

一期五个场景走完，也不等于数十家店都已上线。家数本身还不是名册，见【待确认-42】。建议的顺序仍然是先直营、再加盟，见[项目背景](2.强盛科技POS项目的背景信息.md)。
