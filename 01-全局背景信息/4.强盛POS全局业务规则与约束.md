# 强盛POS全局业务规则与约束

> 更新日期：2026-10-15。
>
> 本文集中写跨模块的硬规则：哪些已经由用户确认，哪些是阶段背景里已经发生过、因此必须守住的边界，哪些只是建议、还不能当规则。项目范围见[项目背景](2.强盛科技POS项目的背景信息.md)，系统边界见[上下游链路](3.强盛POS的定义和上下游链路.md)。
>
> 不在本文里做的事：状态枚举、按钮条件、字段必填。那些放在后续目录。本文没有写到的处理方式，不存在默认方案。

---

## 一、对象归谁

| 对象 | 规则 | 依据 |
| --- | --- | --- |
| 可售库存、门店配额、代销仓库存 | 真相在中枢逻辑库存。POS只有投影和执行回传 | 用户已确认。见[待对齐事项A05](12.待对齐事项.md) |
| 订单路由 | 在中央OMS。POS不选择履约节点 | 用户已确认。ERP一期尚未交付中央OMS，见[待对齐事项A03](12.待对齐事项.md) |
| 主数据 | SKU、价格、门店、组织、导购由上游单向进入。POS不改主档 | 阶段5叙事。时点见[待对齐事项A09](12.待对齐事项.md) |
| 进店销售、支付流水、退货 | POS产生交易记录。库存和财务结果由中枢生成 | 本文与[单据目录](5.强盛POS的单据目录与分层.md) |
| 自提履约单、提货码 | OMS产生。POS只核销 | 阶段5：锁定成功才生成提货码 |
| 代客单 | POS发起，OMS路由，WMS执行区域仓部分 | 阶段5：业绩计入门店和导购工号 |
| 要货 | POS申请。调拨指令和库存结果在中枢 | 落成哪张ERP单据见【待确认-01】 |
| 会计凭证、含折旧净利 | 不在POS | 金蝶是财务底座。指标在指标平台 |
| 采购订单 | 在SRM创建，推给ERP，再推给仓库。POS不产生、不修改 | 用户已确认。与ERP、SRM定稿的差异见[待对齐事项A04](12.待对齐事项.md) |

直营和加盟共用这些归属。加盟多出来的是代销仓、应缴营业款和结算，见[模式说明](7.直营与加盟代销模式说明.md)。

## 二、数量和锁库

| 规则 | POS怎么执行 |
| --- | --- |
| 可卖数量以中枢为准 | 开单保存时，本次数量不得大于该店当前可用。中枢拒绝后，不能改成本地已售 |
| 自提先锁后码 | 没有锁定成功的记录，不核销出库 |
| 核销一次 | 同一提货码已经核销的，再次扫描不得再次扣减 |
| 现货和自提同一本账 | 进店销售扣减的，就是自提已经锁定的那本门店库存。不能卖出已被自提锁定的件数 |
| 代发不扣本店 | 本店无货而改走区域仓时，扣减发生在被路由选中的节点，不在发起店再扣一次 |
| 收货才增加门店库存 | 要货提交、在途都还不是本店可用。以收货结果回传后的中枢数量为准 |
| 盘点不直接改账 | 差异单在授权之前，不改变可售数量。授权之后由中枢调整 |
| 退货回到原库存组织 | 本店售出的退货回到本店微仓或代销仓。货权仍在强盛 |

超卖容差、负库存销售，背景没有给出。在有新的规定之前，不设「允许卖超几件」。

部分提货、锁库超时释放，见【待确认-04】。离线期间同一件高价值商品被卖出的处理，见【待确认-09】。

## 三、离线和支付

阶段背景写明了自提必须实时锁定，没有写离线收银的限额。离线是为了店里断网仍能收下已经允许的交易，不是为了绕开锁库。

| 事项 | 已经能定的 | 还没有写明的 |
| --- | --- | --- |
| 进店收银断网 | 可以写入本地账本的，限于现金，以及支付通道已经返回成功、只是回传中枢失败的结果。联网后按来源单号去重 | 单笔限额、最长离线时间、上传时限，见【待确认-09】 |
| 自提核销 | 断网不能完成核销出库 | 可否先登记待处理队列，见【待确认-04】 |
| 代客下单 | 断网只能存草稿。提交和时效承诺发生在联网之后 | 预占多久失效，见【待确认-06】 |
| 支付结果不明 | 按通道要求查单。不能在POS里手工改成支付成功 | 用哪一家通道，见【待确认-40】 |
| 加盟收款 | 店里可以收款。钱最终经结算归集到强盛 | 商户号归属见【待确认-16】 |

在【待确认-09】关闭之前，设计上不能采用「断网期间不限金额、不限品类」。那会把万象天地那类扑空，换成断网超卖。这是限制，不是已经拍板的限额。

## 四、店务

- 店与店之间的货要移动，必须有调拨申请和收货。没有单据的微信调货，不改变任何一边的可用量。直营和加盟之间、加盟店之间是否允许调拨，见【待确认-26】。
- 收货必须能指回来源出库。数量不一致时另记差异，不在收货单上把实收改成与出库相同来「做平」。
- 报损和试用出库留下原单。是否进金蝶的其他出库，由中枢决定，POS不直接推凭证。
- 盘点期间是否停止销售，见【待确认-15】。
- 加盟店的盘亏在合理损耗之内由强盛承担，超出部分和保管不当由加盟商赔偿。损耗率、计价和SN是否单件判责，见【待确认-23】。没有这些数之前，不在系统里自动生成赔偿金额。

## 五、价格、促销和业绩

- 成交价取下发到店的价格，加上成交当时命中的促销。成交单上留下快照。事后改主数据，不改写已经成交的价格。
- 低于权限的改价要被拒绝。被授权的改价记下操作者、原价、新价和原因。授权到哪一层，见【待确认-51】。
- 加盟店默认使用强盛的零售价。能否在价格带内调整，见【待确认-34】。
- 导购工号记在成交和代客单上。阶段5已经要求代发的业绩计入该门店和该导购。提成比例、计算日、退款是否冲减，见【待确认-13】。制度没定之前，不在POS里用一个自定系数把提成算出钱。
- 业绩如果要改，另作留痕，不直接改掉原单上的工号。是否允许改、谁审批，见【待确认-13】。

促销从哪个系统来，见【待确认-46】。POS不维护第二套促销规则去覆盖中枢。

## 六、日结和加盟营业款

- 交班核对这一班的支付方式和现金。差异留下，不在交班时改写销售单。差异超过多少要升级处理，见【待确认-10】。
- 日结封账之后，这一营业日的成交不靠修改原单来轧差。需要更正时，走退货、调整或下一张单据，具体单据类型在后续设计里定，但不得静默改历史。
- 加盟店日结封账后，应缴营业款由中枢生成。应缴对应的是这家店向顾客收的钱，不包含线上已付款、只到店核销的订单。
- 分成在结算单上计算。POS不在日结界面让店员自行扣下分成。上缴是全额还是净额，见【待确认-17】。
- 结算单上的数量和金额取已经封账的流水。有异议另提差异，不在结算单上改原始成交。
- 储值卡由谁发行、加盟店能否销售、储值资金归谁，见【待确认-21】。未确认前，不把储值消费算进加盟应缴，也不在断网时扣减储值余额。

## 七、留痕

ERP一期不把完整操作日志列为必做。门店不能照抄这条，见[待对齐事项A08](12.待对齐事项.md)。

必须留下的动作：改价、退货、反结账、离线交易的产生和回传、核销成功和拒绝、代客下单、收货差异、盘点审核、交班差异、加盟缴款登记。每条至少有操作者、时间、对象、前后值。

后台直接改数如果发生，必须另有记录。不能靠改数据库把核销时间补齐，也不能把一笔离线交易改成早于断网之前。

商场报送如果发生，上传状态和回执留在报送记录上。报送失败不删除销售单。

## 八、容易和中枢搅在一起的限制

| POS要守住的 | 不要因此扩进POS |
| --- | --- |
| 申请锁库、回传核销 | 不在POS保存一份可以否决中枢的可售账 |
| 代客单带上门店和工号 | 不在POS实现四维路由 |
| 店务单据 | 不指挥区域仓WMS的库位和拣货 |
| 支付流水号 | 不把支付通道的对账文件做成总账 |
| 原始交易号 | 不生成金蝶凭证，不算装修折旧 |
| 加盟店同一套收银 | 不因为加盟就允许负库存、私自调价或不参加路由 |
| 采集序列号 | 不宣称批次和序列号规则在ERP、WMS已经定稿 |

【待确认-01】至【待确认-55】里没有结论的条目，不能在详细设计里被补成「行业通常如此」。名创、小米专卖店、有赞、海鼎的比例和天数只出现在模式说明的对照里，不进入本节的规则。
