# 强盛POS的编码规则和通用字段规则

> 更新日期：2026-10-15。
>
> 本文只写编号、主数据引用和外部号码怎么保存。字段级模板、枚举和校验放在后续产品设计。数据库类型和接口错误码不在这里规定。
>
> SKU、仓库、ERP单据号已经有定稿的，POS直接引用，不另编一套。见[ERP编码规则](https://github.com/TopVitamin/QS-ERP-Project/blob/main/01-全局背景信息/6.强盛ERP的编码规则和通用字段规则.md)。下文标成建议的前缀，正式值都还是【待确认-01】，不能拿去印小票当作规则。

---

## 一、POS自己的单号

### 1.1 格式沿用ERP，前缀另定

ERP单据号是`{前缀}-{YYYYMMDD}-{序号}`，例如`CGDD-20260818-0001`。日期是创建日，序号同类型同一天从0001起，超过9999位扩成5位，作废后不重用。单号里不拼来源单号。

门店面向国内店员，建议使用同一格式。这是建议，不是已经和ERP共同签过的号码段。

建议的生成方式：

- 前缀用单据中文名的拼音首字母，2至6位大写字母，同一类型固定。
- 保存时生成，用户不能改，删除或作废后不重用。
- 和OMS、ERP的关联放在来源单号字段里。提货码、电商订单号、支付流水号不拼进POS单号。

### 1.2 建议前缀

正式前缀没有确认。下表只避免和ERP已占用的前缀撞车，方便讨论。印在小票上之前必须先改掉「建议」两字。全部见【待确认-01】。

| 对象 | 建议前缀 | 示例 | 说明 |
| --- | --- | --- | --- |
| POS销售单 | MDXS | MDXS-20260818-0001 | 不使用XSDD。XSDD是ERP的B2B和独立站销售订单 |
| 退货单 | MDTH | MDTH-20260818-0001 | 是否改用XSTH，见【待确认-01】 |
| 代客单 | DKXD | DKXD-20260818-0001 | 不是仓库出库单号 |
| 核销记录 | ZTHX | ZTHX-20260818-0001 | 也可以只做履约单下的行记录。是否独立成单，后续再定 |
| 要货单 | MDYH | MDYH-20260818-0001 | 不使用CGDD |
| 收货单 | MDSH | MDSH-20260818-0001 | 不使用CGSHTZ |
| 差异单 | SHCY | SHCY-20260818-0001 | |
| 盘点单 | MDPD | MDPD-20260818-0001 | ERP一期没有盘点单前缀 |
| 退仓单 | MDTC | MDTC-20260818-0001 | |
| 店间调拨申请 | MDDB | MDDB-20260818-0001 | 是否改用FBDB或ZJDB，见【待确认-01】 |

支付流水、钱箱事件、操作日志、锁库申请如果不能单独被业务人员引用，可以不发业务单号，只保留通道流水号或内部标识。

## 二、主数据编号不另编

| 对象 | 规则 |
| --- | --- |
| 商品 | 沿用ERP商品编码。POS不建SPU，不按门店重编SKU |
| 条码 | 引用主数据里的条码。POS不发第二套店内条码 |
| 门店 | 沿用上游组织或门店编码。编码规则若尚未定稿，不在POS先编一套临时店号当主键，见【待确认-42】 |
| 导购 | 沿用工号。POS不把登录名当成业绩主键 |
| 仓库 | 微仓、代销仓、区域仓引用中枢的逻辑仓编码（ERP定稿是`LWH`加6位序号）。POS不因为加盟再编一种仓库码 |
| 收银台 | 是否由主数据下发见【待确认-01】。未定之前，收银台号只在本店内区分，不写成公司级主数据 |
| 展示 | 引用时用Code-Name：编码和名称之间一个空格，例如`LWH000001 示例门店微仓`。接口仍传编码或内部标识，不把名称拼进主键 |

导购登录名怎么编，背景没有规定。不要把工号直接当成唯一登录名的生成规则之外再发明一套姓名账号。登录名和工号可以不同，业绩始终挂工号。

价格、币别、税率在POS上出现时，取值来自已经下发的资料。POS不维护第二套币别。展示单价、金额时，沿用ERP已确认的精度：单价4位小数，金额和税额2位小数。这是展示约束。POS不重算存货成本。

门店一期在国内，币别按人民币展示。不做多币种跨境门店。

## 三、外部号码

| 号码 | 怎么存 |
| --- | --- |
| OMS履约单号、ERP结果单号、调拨出库单号 | 按原样保存，用作关联和去重，不改格式 |
| 小程序或电商平台订单号 | 普通外部单号。不参与POS单号 |
| 动态提货码 | 按中枢生成的原值保存。POS不重新编码，也不把提货码当成销售单号 |
| 支付通道流水号 | 原样保存。查重范围是同一通道下的流水号。支付是否成功以通道结果为准，不以号码格式为准 |
| 商户号 | 文本。加盟店用强盛的还是加盟商的，见【待确认-16】 |
| 序列号、IMEI | 文本，挂在商品事件上。哪些商品必填见【待确认-11】【待确认-12】 |
| 商场回执号 | 仅在需要报送的店保存。没有租约要求的店不产生这个号码 |

数电票如果由财务或开票系统开出，发票号码按20位保存，没有发票代码。开票系统是哪一套、票头是谁，见【待确认-31】。POS采集顾客要的抬头，不等于已经开票。

## 四、去重

同一笔店内交易在离线回传、支付查单、核销重试时可能到达中枢多次。去重键是「来源系统 + 来源单号」，支付再加通道流水号。重复到达不得第二次扣减库存，也不得第二次计入营业额。

这个键的具体字段名在后续接口设计里定。本文只规定：重试不是一笔新交易。

## 五、不在本文规定的内容

- 各对象的字段清单、必填、长度和枚举。
- 小票模板和打印机型号。
- 把建议前缀写进条码的实施步骤。
- 提货码的位数和刷新频率。

后续字段设计引用主数据时，默认Code-Name。例外要写明原因。建议前缀在确认前，原型里的单号只是演示，不能回写成规则。
