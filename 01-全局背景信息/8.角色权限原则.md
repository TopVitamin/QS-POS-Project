# 角色权限原则

> 更新日期：2026-10-15。
>
> 本文只写数据能被谁看见、哪些动作必须另行授权。角色的名称、菜单和审批层级没有定稿。组织架构见[公司背景](1.强盛科技公司业务背景信息.md)，它不映射成账号。
>
> 字段级权限、按钮和岗位说明书放在后续目录。

---

## 一、职责不是角色

阶段背景里能分清的是职责，不是已经建好的角色：

| 职责 | 在POS里需要做的事 | 默认不做什么 |
| --- | --- | --- |
| 导购 | 开单、核销、代客下单、查看自己的业绩归属 | 不改价格主数据，不封别人的班，不看其他加盟商 |
| 收银 | 收款、退款、交班 | 不审核盘点差异，不改应缴营业款 |
| 店长 | 本店要货、收货、盘点、看本店日报 | 不路由全渠道订单，不建SKU |
| 新零售 / 总部运营 | 看直营店的交易和店务，处理授权范围内的异常 | 不在POS里做总账 |
| 财务 | 看日结、支付流水、加盟应缴和结算结果 | 不在POS里付款、不生成凭证 |
| 加盟商管理 | 维护合同配置的查看，范围只限本加盟商 | 不看其他加盟商的价格、营业额和结算 |
| 系统管理 | 开通账号、分配数据范围 | 不绕过锁库和改价限制 |

一个人可以兼两样职责。兼岗不自动扩大数据范围。店长兼收银，仍然只能看被授权的店。

ERP一期的权限是RBAC，有权限即可提交和审核，并且允许本人审核本人创建的数据。POS是否完全沿用，背景没有单独规定，见【待确认-51】。在没有新的规定之前，不建设多级会签。高风险动作仍然要留下授权记录，不能因为「还没有多级审批」就允许静默改价。

## 二、数据范围

| 范围 | 规则 |
| --- | --- |
| 本店 | 导购、收银、店长默认只看本店的销售、库存投影、履约单和班次 |
| 多店 | 只有被明确授权的总部人员可以跨直营店查看。授权到店，不到「全部未来新店」 |
| 本加盟商 | 加盟商的管理人员和财务只看该加盟商名下的店、代销仓、应缴和结算。看不到其他加盟商，也看不到直营店的成本 |
| 顾客信息 | 核销当时可以看完成本次履约需要的提货信息。加盟店列表里的手机号是否脱敏，见【待确认-52】。在此之前，列表不展示核销用不到的顾客字段 |
| 成本 | 存货成本和供应商价格不在门店端展示。POS不因为要算毛利就把成本下发到收银台 |

代销仓的数量，本店人员要能看见本店可用和已锁定，否则无法解释为什么不能卖。区域仓还能订多少，加盟商是否可见，见【待确认-25】。

会员如果在直营和加盟之间共享，顾客在另一家店的资料会跟着出现。共享范围见【待确认-37】。未确认前，不把跨店共享写成已经开通。

## 三、必须另行授权的动作

下面这些动作和普通开单分开。谁有权批准，见【待确认-51】。

| 动作 | 为什么要分开 |
| --- | --- |
| 改价、赠送 | 零售价的源头不在POS。改价只影响这一单，并留下原价和新价 |
| 反结账、作废已回传的交易 | 可能把已经扣过的库存和营业额改掉。作废必须回传中枢，不能只改本地 |
| 无原单退货 | 没有原销售单时，库存和退款都缺少对照 |
| 跨店退 | 涉及两个收款主体或两个保管人，见【待确认-27】 |
| 盘点差异过账 | 差异在授权前不改变可售数量 |
| 离线开关和超限额 | 离线是例外通道。打开和超限都要有人、有时间 |
| 修改已封账日结 | 封账后不改原单。若允许重开，重开本身就是一条日志 |
| 查看全部加盟商结算 | 分成和营业额属于经营数据，不随「能登录总部」自动打开 |

加盟店店员如果是加盟商的员工，强盛仍要看到工号上的业绩归属，以便核对代发。提成的钱由谁发给店员，见【待确认-36】。发放方不同，不改变「工号必须记在单据上」。

## 四、账号从哪里来

- 强盛员工的工号从上游主数据来。POS不新建一套与工号无关的人员主档。
- 加盟商账号和强盛员工分开。加盟商不能给自己开通其他加盟商的权限。
- 一家加盟商可以有管理人员、财务和门店账号。三种都只落在本加盟商的数据范围内。子账号由谁创建，可以后续再定，但创建人是谁都不扩大范围。
- 离职、停业、合同终止之后，账号停用。停用前已经产生的单据保留，供审计查阅。

加盟商用小程序还是网页查看应缴和结算，见【待确认-38】。那是入口形态，不是另一套权限模型。

## 五、和审计有关的底线

不管以后角色表怎么命名，下面几条都先守住：

1. 加盟商之间的营业额、分成和结算互相不可见。
2. 改价、反结账、离线补传、盘点过账有操作者和前后值。
3. 有菜单权限，仍然不能绕过「中枢拒绝锁库则不能卖」。
4. 系统管理可以授权，不能直接改数据库把核销补成成功。

《监管规则适用指引——发行类第5号》5-14关注谁能查看、谁能修改，以及过度授权和直接改库。指引见[证监会页面](https://www.csrc.gov.cn/csrc/c101802/c7118278/content.shtml)。门店收入是否进入信息系统专项核查，由中介判断。日志要求不依赖那个判断，见[合规与审计要求](9.合规与审计要求.md)。
