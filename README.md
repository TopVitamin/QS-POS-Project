# QS-POS-Project

这是基于「强盛科技」虚拟企业的门店交易和店务触点设计仓库。公司自己做品牌和渠道，生产放在代工厂。POS负责进店收银、到店核销、代客下单和门店微仓的店务。锁库、路由、业财和主数据在中枢，法定核算在金蝶。

> 强盛科技的时间、规模和业务数据都是课程演练用的虚拟内容，不代表任何真实企业。

## 仓库目录

```text
01-全局背景信息/    公司门店侧、POS范围、上下游、全局规则
09-产品原型/        管理端、收银端、移动端的前端原型Demo，全部mock数据
```

原型的设计说明见[前端设计说明](09-产品原型/前端设计说明.md)。原型只证明流程表达，不作为规则来源。

和本仓库配套的公开设计仓库：

- [QS-ERP-Project](https://github.com/TopVitamin/QS-ERP-Project)：后台业务中枢。采购、销售、库存单据和编码以它的定稿为准。它的一期不包含POS和中央OMS。
- [QS-WMS-Project](https://github.com/TopVitamin/QS-WMS-Project)：仓内作业。它的立项范围是四个海外仓，和阶段5叙事里的国内五仓、门店微仓不是同一时点。
- [QS-SRM-Project](https://github.com/TopVitamin/QS-SRM-Project)：供应商协同门户。采购订单在SRM创建、推给ERP、再推给仓库；这条和POS关系不大，差异见待对齐事项。
- [QS-JXC-Project](https://github.com/TopVitamin/QS-JXC-Project)：更早的进销存演练。
